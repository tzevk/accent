# Approved cost budgets are their own record, compared only on matching scope and currency

Ticket #321 makes the budget half of the company expenditure report real: an authorized operator records a Project cost budget, submits it, approves it with its evidence, and the report compares it with Incurred Project Cost. This record fixes the decisions later slices (financial close, export, revisions) must keep.

A cost budget is not a field on `projects`. `projects.project_value`, `projects.cost_to_company`, `projects.budget`, quotations, purchase orders, and proposal values are commercial context: they describe what the client might pay, not what the Project is approved to cost. Reading any of them as a budget would silently convert a sales figure into a cost control. The slice therefore adds `project_cost_budgets`: a Project, an amount, a currency, a scope, a period, approval evidence, a lifecycle state, and a version, with `project_cost_budget_events` as its append-only journal.

A budget is compared with confirmed Incurred Project Cost only when all four dimensions match: the same Project, the same currency, the `project_incurred_cost` scope, and a month inside the approved period. Nothing is converted: a USD budget never compares with an INR row, and the report says so. A `commercial_value` scope exists so a recorded commercial figure is stated as commercial and never compared as a cost budget. Where several approved budgets match, or where an approved budget has no confirmed cost beside it, no variance is invented — the outcomes `ambiguous`, `unsupported_incurred_cost`, and `no_incurred_cost` are published instead, beside `missing`, `unapproved`, `incompatible_currency`, `incompatible_scope`, and `incompatible_period`.

Only `approved` is an approved budget, and only an explicit `approve` command that carries approval evidence sets it. Recording, editing, submitting, and withdrawing are versioned commands on the same contract as cost commands: stale versions are refused, disallowed transitions fail, a withdrawal needs a reason, and each accepted command appends one immutable journal row. Approving a later budget that overlaps an earlier approved budget of the same Project, currency, and scope supersedes the earlier row instead of deleting or rewriting it, so a later closed-period review still reads the amount, evidence, version, and journal the month was compared with.

The comparison is an isolated section of the reconciliation payload (`budgets`). A budget never enters Company Incurred Cost, the Project breakdown, or the evidence summary, and remaining or overspent budget is labelled for what it is: the difference between an approved cost budget and confirmed Incurred Project Cost for one month. It is not profit, recognized revenue, or a forecast of uncommitted future work, and the response and the screen both say so.

The public interface is `recordCostBudget`, `executeBudgetCommand`, `fetchProjectBudgets`, `fetchCostBudget`, `fetchBudgetJournal`, and `CompanyReconciliation.budgets` in `src/lib/company-expenditure/index.ts`; the routes under `/api/admin/cost-budgets` and the report's budget section call that interface only. Budget reads, writes, and approvals reuse the existing source privileges — `other_expenses:read` / `other_expenses:update` / `other_expenses:approve` — and never Project Activity access. Commands accept the caller's connection so the later financial-close slice takes one coherent snapshot across cost and budget sources.
