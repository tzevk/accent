# Presence silence is counted from activity evidence

`user_presence` carried one timestamp, `last_seen`, and every tracked event refreshed it — including the 120-second heartbeat that reports the User idle. The staleness sweep counted silence from that one column, so an open-but-idle tab refreshed its own staleness forever: the sweep never fired while the tab lived, and the Work Session the tab held stayed open across every hour the User spent away from the desk. One timestamp that an idle heartbeat moves cannot tell a User who is working from a browser that is merely alive, and the span read from it overstated the day by exactly the time nobody worked.

We decided a Work Session's staleness is counted from the last activity signal, not the last heartbeat. `user_presence` gains a nullable `last_active_seen`, refreshed by active evidence only — a heartbeat reporting not-idle, a status change to active, a page view, a logged action — while an idle heartbeat refreshes `last_seen` alone. The sweep keeps its ten-minute window and its five-minute schedule; the staleness key becomes `COALESCE(up.last_active_seen, up.last_seen)`. The effective end therefore lands about fifteen minutes after the last real input, and never more than about seventeen: the five-minute client idle threshold, up to two minutes of heartbeat lag, and the window. A row written before the column existed holds no activity signal at all, so that row falls back to its `last_seen`; without the fallback a NULL would read as instant silence and the first run after the deploy would end live Work Sessions. The fallback is also why no backfill runs — existing rows are read correctly as they stand. A User with no presence row at all is unchanged: silence by the repo's own presence rule (`getStatusFromActivity` reads a missing row as offline), swept and stamped with the moment the sweep noticed.

The accepted trade-off: a desk interruption longer than the window — reading, a meeting, a long call — ends the Work Session. That is deliberate, and it is the price of no idle tab holding one open. The end the sweep writes is an inference about presence, never a close the User chose: it is marked `end_source = 'sweep'`, distinct from the `logout` and `beacon` ends the browser reported, and the Punch Out tile discloses the inferred end as inferred, as the attendance panel reading the same field does. The alternative is trusting a heartbeat that only says the browser is alive, which is exactly what let an idle tab hold a session for hours, so the trade is stated rather than hidden.

Considered: keeping the heartbeat as the staleness key and shortening the window instead. Rejected — a window short enough to catch an idle tab would sit barely above the heartbeat's two-minute cadence, so one late heartbeat ends a working User's session, and it would drift away from the ten-minute offline threshold the presence dot already publishes. Refreshing `last_seen` only for active evidence was rejected, because that column is what the presence dot, the presence list's recency sort and the live-monitoring reads measure (`getStatusFromActivity`, `/api/user-status`, `/api/active-users`): an open tab being read is still at the desk, and its own status must not change. Backfilling `last_active_seen` from `last_seen` was rejected for the same reason the fallback exists — it would relabel every stored heartbeat as an activity signal, which is the claim this record refuses to make.

This is the first record in this area, so the domain line is written down: a Work Session is not a Session, not Time Present and not a Punch. A Session is the authenticated login revocation acts on, Time Present is the device-measured office span, and a Punch is a device event (ADR-0007). The Work Session is only the browser's reported span, and a sweep-stamped end is an inference that work stopped — not a close, and not an attendance fact. No Work Session figure reaches payroll: the span feeds the day's Total Time (`user_daily_summary.total_work_minutes`, read by `/api/work-summary`), while pay is priced from Logged Hours (ADR-0010) and the Attendance Record stays authored by HR or measured by the device. A future reader must not merge them, because doing so would re-price payroll.

Consequences: a day's Total Time now sums spans that stop when the User stops, so a User who leaves the tab open reads a shorter figure than before — the figure the work actually justifies. An idle end becomes ordinary rather than exceptional, so the inferred-end disclosure is load-bearing rather than decoration: it is what keeps a sweep end apart from the logout the User chose. Nothing else about the sweep moves — the same one query, the same close path, the same ten-minute window, and the sweep stays idempotent and rerunnable because only `status = 'active'` rows are touched and the read falls back. The three figures behind the effective end are one computation (five minutes of client idle threshold, two minutes of heartbeat lag, ten minutes of window), so a later change to any of them must be read against the end stated here.
