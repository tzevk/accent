# Device punches override stored times; status stays human-authored

The employee attendance grid now merges Smart Office `attendance_logs` punches into `employee_attendance` cells (server-side in `GET /api/attendance`). We split the authority: on any day with punches, derived `in_time`/`out_time` and `overtime_hours` (worked − 8h, kept only past the 2h gate) **re-derive from the device on every reload and clobber stored values** — manual time/OT edits on punch-days are display-transient. Status (`P`/`HD`/leave/`WO`/`H`) remains human-authored: punches only prefill `P` into _empty_ cells and never change an existing status. Saves persist the displayed device times so `employee_attendance_summary` (std in/out) and payroll's attendance snapshot see real punches.

Considered: stored-wins (punches fill only cells with no saved times). Rejected because a saved manual time would silently diverge from the device forever with no signal — the grid would show times the device disproves. Punches-always-win keeps one precedence rule instead of a split brain (device wins time, human wins status), and the device is the only source that observes every day, including days nobody edited.

Consequences: half-day intent survives via `hoursForDay` capping `HD` at 4h regardless of injected span, and no OT derives on `HD` days. Days where punches contradict an authored leave/WO/absent status surface a tooltip warning rather than an automatic correction. The project-activity-day `P` prefill was removed — punch evidence replaced it — so employees without a mapped `smartoffice_code` have a fully manual grid.
